# 规则迁移复测 · 2026-11-01

使用真实 API、相同观察与提示、low 推理档位。四个改换数值/机制约束的构造局面，各换两种动作编号与排列；每模型八次请求。先写入 `blind-review.json`，再打开 `model-key.json`。不是实际天梯录像或胜率测量。

| 模型 | 人工评分 | 有效回答 | 成功回答耗时中位数 | 已报告 token |
|---|---:|---:|---:|---:|
| Sol | 13/14；把未返回请求计零则 13/16 | 7/8 | 5.963 秒 | 32051 |
| Terra | 11/16 | 8/8 | 3.638 秒 | 37501 |

评分每次 0–2：正确首步与关键后续均成立为 2；首步合理但后续存在关键错误为 1；丢失可用解法为 0。未完成请求单列，不能算作卡牌规则答错。Sol 的失败耗时约 12.15 秒，旧记录仅保存 `AdvisorError`，不足以确认具体原因。

两者仍各出现一次“十费先打零费硬币得到十一费”的错误后续。Terra 另一次把伤害误当成降低攻击力，并在脆弱风怒随从的复生交换中漏算其死亡。Sol 在这组返回答案中较稳定，继续选用 Sol；样本小，不能推断长期天梯胜率。

该轮同时加入通用机制提示与“先给简短结论、再给匹配动作 ID”的结构顺序，无法将变化归因于单一改动。评测调用的是模型选择接口；生产程序每步还会重读真实局面，因此错误的长线解释也不必然等于实战执行了全部错误后续。

复测后的软件修复已落实：

- `resource_facts.py` 读取实际法力上限、当前费用和加费随从，计算硬币收益、溢出及条件费用表。条件表不冒充合法出牌序列。
- `tactical_checks.py` 在范围很窄且状态充分可知的凝视目标局面，计算吸血、圣盾、剩余攻击与有效生命；只在唯一目标能防住可见场攻时本地选择。未知效果或其他后续行动空间交回模型。
- 提示明确风怒随从第一次攻击死亡后没有第二次攻击、伤害不扣攻击力。
- 每局结束生成客观复盘记录，未确认动作和输局进入有界待复盘队列。没有自动改写策略或模型权重。

所有试题、回复、评分、编号与用量均保存在本目录，可重查判断依据。
