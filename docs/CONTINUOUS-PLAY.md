# 连续标准天梯

用户明确要求持续天梯、不设次数或时间配额、正常对局不要打断。0.2 原生界面提供「开始自动天梯」「人机练习」「打完这局停止」「立即停止」。自动天梯通过 stdin 的 `mode=ranked_auto` 进入；人机练习仍只跑一局。

## 运行与停止

- 自动天梯没有局数、对局时长、动作数或累计 API 调用/token 配额。每局保存真实结果、回收该局进程并恢复 FPS，间隔 10 秒启动下一局；开局重新核对资源、标准模式与完整牌表。
- 正常赢/输/平继续。三局未复盘只设置 `review_due`，不会停止。连续三败、未完成、未确认动作、未核实起手或清理失败会暂停，等待针对问题的复盘。
- 「打完这局停止」只写局后请求，并把焦点交回炉石；控制器在单局返回后读取请求。短暂焦点交接只允许重试明确尚未发送输入的拒绝，不能重放已发送或未确认的动作。
- 「立即停止」、退出应用、真实资源风险、API/观察/输入错误仍可立即停止。关闭客户端不会暂停服务器上的对局，故障必须记为未完成，不能冒充正常结束。
- 计划中的分析、安装、更新及重启都在局间进行。活动对局期间仅阅读有界日志，不切换焦点、不点击界面、不替换运行组件。

## 本地记录与复盘任务

数据目录为 `~/Library/Application Support/HearthstoneAI`。密钥不出现在以下文件中。

| 文件 | 含义 |
|---|---|
| `learning/autoplay-state.json` | 当前连续运行的 ID、PID、状态、已返回局数、最近 16 次运行、复盘进度和停止原因 |
| `learning/match-history.json` | 最近 50 条结果及用量/资源/确认汇总，只有 `WON/LOST/TIED` 才是完成的对局 |
| `learning/review-queue.json` | 最多 10 个待复盘公开局面，不直接把最后一步当作败因 |
| `learning/review-ack.json` | 复盘任务写入当前 `autoplay_id` 和已审查的 `completed_games`；旧 ID 无效 |
| `learning/pause-after-game.json` | 局后停止请求；`reason=user_requested_stop` 尊重用户停止，`reason=review_update` 等待局间更新；消费后删除 |

每 15 分钟的 Codex 心跳任务读取已结束对局，正常时不停止软件、不重复启动；需要修改时先写局后请求，等该局自然结束再改。用户停止或退出后不自动重启。分析是程序规则/策略/执行的改进，不是模型权重微调；游戏本身的运行不依赖心跳任务。

## 仍保留的边界

游戏内存采样 1800 MiB、AI 进程组 200 MiB；保持温度、电源、电量、CPU 和磁盘检查。内存压力读取 macOS 导出的 normal/warning/critical 状态；critical、可用内存指标低于 20%，以及相对连续运行基线的 swap 增长超过 256 MiB 都会停止。warning 记录并通过局间清理处理；历史 swap 总量不再单独阻止启动；各局共用基线，不通过换局重置累计增长。FPS 临时设为 30，退出恢复。单次请求输入最多 64000 字节、输出 1536 token、网络子进程 18 秒；启动、数据恢复与动作确认的超时不等于对局时长配额。

只保留最近五局详细日志；每局 Power.log 8 MiB、事件 1 MiB、决策 2 MiB、动作输出 4 MiB。去除累计配额不会导致日志、进程或内存无限积累。采样保护不等于内核硬限制；连续运行和完整标准天梯仍需要实际验收。

每局收尾回收该局 AI、API 请求、守护与本次启动的游戏进程，并显式关闭 stdin/stdout/stderr、日志和锁文件；新局使用新的局面解析与模型上下文。长期父进程只保留有界运行列表与界面日志。此清理在对局自然结束后执行；不会为了定时清理而中断健康对局，也不强行清空操作系统 swap。2026-11-01 用户明确接受以定期清理与实际增长检查防止资源累积。
