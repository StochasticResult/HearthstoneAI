# 棋力改进记录

这里的“训练”是对应用的规则、上下文、策略和执行进行可复现改进。目前没有提交 OpenAI 微调任务或改变基础模型权重。

## 模型选择

2026-11-01 的基础盲测中，Luna 的可接受首步为 6/16，Sol、Terra 均为 16/16。两者高级题都为 22/24 个可接受首步；考虑后续计算和对手应对后，人工总分 Sol 65/72、Terra 62/72。随后四题迁移复测继续偏向 Sol，但 Sol 有一次未返回有效答案。当前应用已保存 `gpt-6.1-sol`；它更慢，实际胜率尚未验证。

数据与盲评：[基础比较](model-comparison-20261101/README.md)、[复杂局面](hard-comparison-20261101/README.md)、[迁移复测](rule-transfer-20261101/README.md)。历史结果文件保持原样；当前源码的观察和规则已经继续更新，重跑不等于复刻旧提示。

## 已落实的经验

| 暴露的问题 | 程序改动 | 验证 |
|---|---|---|
| 硬币加减、十费上限、先花费还是先硬币 | 从日志读取永久/临时/已用/锁定法力与 MAXRESOURCES；本地计算当前硬币效果与条件费用表 | 真实日志字段核对；零费/加费/二十费上限/未知上限/过载测试；双加费七费随从留出题 |
| 吸血被错误限制为目标剩余生命；伤害被当成扣攻击 | 小范围本地凝视计算器，包含圣盾、免疫、血上限、护甲、风怒；未建模效果不自动决定 | 原题、换数值题、圣盾题、回复上限和未知效果拒绝测试 |
| 复生第二次亡语、脆弱风怒损失第二次攻击 | 通用规则提示；有限卡牌的见证序列校验器 | 四个复杂斩杀序列及两个反事实序列计算到精确斩杀；不是完整炉石模拟器 |
| 生成牌被当作原始牌表证据；对手手牌被当成已知 | 只用公开原始出牌匹配来源模板，未见关键牌带条件；已知手牌/奥秘必须有公开来源，洗回与变形撤销记忆 | 候选模板、隐藏字段、生成牌、公开回手/洗回及双方仪式分离测试；4 道真实 API 检查通过 |
| 候选动作过时、图像与实际场面不一致 | 日志与 Mirror 交叉核对，执行前重验，等待客户端及服务器确认 | 实际人机记录和过时建议/选择确认回归用例 |

资源读取参考 [HearthSim 的 GameTag 定义](https://github.com/HearthSim/python-hearthstone/blob/master/hearthstone/enums.py)；过载与临时法力的计算同时核对了 [Fireplace Player 实现](https://github.com/jleclanche/fireplace/blob/master/fireplace/player.py)。这些社区实现不是暴雪完整规则保证；生产仍以实际合法动作菜单和每步重新读取为准。

## 每局如何留下可复盘材料

`decisions.jsonl` 保存当时的公开观察、候选动作、模型回复及随后确认事件。`review.json` 只把明确的 `WON/LOST/TIED` 当作完成结果，其余为 `INCOMPLETE`，同时保存 API 用量、决策耗时和采样资源峰值。

应用数据目录下 `learning/match-history.json` 保留最近 50 条汇总；`learning/review-queue.json` 最多保存 10 个有界公开局面。未确认动作与输局最后决策进入待复盘队列，标签只是“需要检查”，不自动认定那一步就是败因。生成报告不调用 API、不复制原始账号日志。

改进顺序是：查实际公开状态和输入确认 → 区分规则/资源计算、策略取舍、观察或操作失败 → 写入通用规则或小范围计算 → 原题与换数值题检查 → 人机验证。对手未知手牌与随机结果继续保持不确定性。自动天梯在正常对局后继续排队；故障、未确认动作或连续三败会停止继续排队，先复盘再启动。每 15 分钟的复盘任务只读取日志；计划中的改进与重启均等待本局自然结束。详见 [连续运行](CONTINUOUS-PLAY.md)。

## 仍需验证

- 这组构造题中好的解释，不保证模型能在全部后续局面正确执行。
- 起手仍全部保留，策略换牌尚未通过输入校验。
- 多局稳定性、其他窗口尺寸和地点等复杂效果仍未验收；标准天梯入口已接入严格模式校验，真实结果见验证记录。
- 新模型及加速操作的实战结果记录在 [VALIDATION.md](VALIDATION.md)，不能用旧 Terra 成功局替代。

## 应用内的赛后自训练

当前由 Codex 每三场天梯复盘。`learning/review-owner.json` 的 `owner=codex` 同时暂停原生「立即训练」和定时评审。应用在申请钥匙串或调用评审 API 前检查归属。已有的经验仍按每局固定的版本使用。用户明确把复盘交回应用后，才能恢复原生付费评审。

「策略与自训练」保存评审模型、推理强度、最近 1–5 局、15–1440 分钟的定时间隔，以及对局经验、Luna 备用和多步计划的设置。原生评审默认 `gpt-6-astra max`、最近三局，定时默认关闭，启用时默认每小时一次。对局模型独立设置，首次安装默认 `gpt-6.1-sol fast medium`。

原生应用打开时负责计时。恢复唤醒或重新打开后，已到期的定时任务最多补做一次。手动与定时共用一个进程锁。软件先查找自上次成功训练以来有完整记录的标准天梯，再检查资源、读取钥匙串并调用 API。未结算、人机和资料不全的场次不送审。训练失败保留上次成功的进度和策略。每次最多采用设定的近期局数，较早的场次可能落在窗口外。程序保存最近 24 场压缩回放和最近 8 次本机报告。回放包含所有留牌、动作建议、合法备选与游戏回执。动作、撤回、超时、未执行的备用建议和回合交界的提交分别标注。

模型返回逐局复盘以及带反例的经验。程序核对两条已确认的真实决策、可选的替代动作、适用阶段与可见卡牌，再发布有限数量的文字建议。每局开局固定经验版本并与实际执行文件版本分别记账。相同局面下 Sol 和备用 Decisions 都可以参考这些建议。卡牌效果更改后，绑定旧卡牌文本的建议失效。游戏动作仍经过现有的合法性、回执与多步重新校验。可在设置页查看报告、建议及例外，或取消「在对局中使用已学经验」。这些经验影响决策输入，模型权重不变。

对局默认用简短的战术标签说明动作。Sol 仍在完整的公开局面和合法菜单上进行推理，已验证的多步计划继续使用。只有一个已完整列出的合法动作时可由程序直接选择，执行后仍等游戏回执。有未支持的选项时不能据此假定动作唯一。牌局的决策摘要和复盘报告按模型汇总服务端报告的输出、推理、输入和缓存输入 token，缺失的用量保持未知。局后应用日志也显示输出和推理计数。

耗时较长的原生评审使用 Responses 后台任务，保持 `store=false`，通过同一任务编号查询结果。OpenAI 为查询短暂保留后台响应。程序保存一份有界的待评审回放和任务编号。中断后继续取原任务，取得结果后才发布策略。若提交后未收到编号或结果已无法取回，费用未知的这批会单独记录，不会自动重新付费。复盘默认使用普通服务档，保留用户为评审选择的模型与推理强度。
