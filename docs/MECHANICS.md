# 公开机制与操作覆盖

目标是按游戏机制统一读取与校验，不依赖遇到某张牌再增加牌名分支。模型收到当前属性、公开效果、卡牌文本与实时合法动作；它不是本地完整规则模拟器。以下覆盖不等于证明最佳打法或每张卡都经过真实对局。

| 机制 | 已实现 | 验证与边界 |
|---|---|---|
| 武器 | 双方攻击、实际剩余耐久、效果与附魔；己方英雄攻击使用实际目标列表 | BE_227 真实失败日志回放恢复为 0 攻 3 耐久。优先显式 DURABILITY，否则实际 HEALTH−DAMAGE；不猜非零属性 |
| 地标 | 双方位置、占位、耐久、冷却、效果；己方合法激活与目标输入 | 合成日志、Mirror 身份/位置交叉核验与输入计划测试；尚无真实激活验收 |
| 任务/任务线/支线/持续目标 | 公开目标身份、进度、总量、倒计时及脚本计数；卡扎库斯自定义效果另有实际组件解析 | 按目录机制识别，不把普通隐藏奥秘身份传给模型；各阶段换卡按新实体/卡 ID 读取，未观察到的进度保留未知 |
| 奥秘与记牌 | 数量、公开已知身份、已知手牌来源、试探记录、己方剩余组成和对手候选模板 | 保留原有隐私、生成牌/洗回/变形失效检查；不是全量奥秘候选排除器 |
| 战斗状态 | 护甲、圣盾、嘲讽、冻结、潜行、免疫、吸血、剧毒、复生、休眠、沉默、突袭、冲锋、多次攻击、法强、亡语及目标限制 | 属性来自当前日志；实时选项决定能否行动，不能用“未疲劳”替代合法性 |
| 英雄牌/技能 | 公开双方英雄技能；手牌英雄/武器/地标可出牌；需要目标的技能/战吼有二阶段输入 | 普通术士技能已有实战；新增目标技能为离线验证 |
| 附魔和玩家持续效果 | 公开实体与玩家上的效果文本、两个脚本计数；相同附魔合并计数 | 30 次相同附魔不再撞旧 12 条上限；独立类型最多 64 条，单次请求仍有资源上限 |
| 通用选择 | 原有 3/4 项发现与 TARGET 的单目标选择使用真实实体列表 | 已实测发现、仪式目标；通用 TARGET 不依赖某张牌名，拒绝隐藏或不匹配实体 |
| 未支持的交互 | 显式保留缺口，不能把未知类型或嵌套选项当成出牌/攻击 | 可交易、锻造、泰坦技能等独立 UI，以及非 3/4 项卡片选择尚未完成操作验收。不能因过滤它们而自动声称“只剩结束回合” |

读取对方公开牌不要求程序能操作那张牌。以上未支持的己方交互仍是明确缺口；若当前只剩未支持交互与结束回合，程序报明原因，而不是自动空过。对方武器/地标/任务的存在本身不应触发“不支持类型”退出。

局部算术快捷规则必须拒绝其未建模的地标、玩家持续效果、公开任务和额外战斗状态，把判断交回包含这些事实的模型。未知字段不能默认为零或不存在；对方回合持续解析，不在效果传播到一半时要求可操作快照；我方缺少必需字段则有界等待刷新。

回归覆盖包含：目录中 492 个武器、101 个地标的统一属性模式，以及 76 个公开目标 ID；这些是生成数据的结构测试，不是 669 张卡的逐张实战。真实操作与长期连续运行继续按 `VALIDATION.md` 记录。
